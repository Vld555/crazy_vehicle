## BR-02 — дробная граница достаточности дров

- Источник: SPEC 3.4.1, 3.4.2 и 5: ровно достаточный запас разрешает действие,
  но правило допуска при сравнении float отсутствует.
- Воспроизведение:
  ```python
  hut = WalkingHut("Избушка", 1000, 2, 0.0014)
  hut.walk(0.07)
  ```
- Математически расход равен 0.0014, но вычисление по формуле SPEC даёт
  `0.07 * (1000 / 50000) == 0.0014000000000000002`.
- Текущий результат: HutOutOfFirewood, всё состояние сохранено.
- Вопрос автору: требуется ли допуск сравнения и обнуление остатка? Если да,
  указать точное правило и добавить regression-TC. Приближённые сравнения
  результатов в тестах сами по себе не определяют допуск достаточности дров.
- Статус: ожидает решения автора. D использует буквальное сравнение `firewood < cost`
  и вычитание по SPEC, не вводит дополнительного допуска. 55 авторских TC проходят.

## BR-03 — целые числа, не представимые конечным float

- Источник: SPEC 3.2 разрешает int/float и требует конечность, а 3.4.1/3.4.8
  не ограничивают положительные расстояние и количество сверху.
- Пример: `hut.walk(10**1000)` или, сидя, `hut.add_firewood(10**1000)`.
  Python int конечен, но `float(10**1000)` вызывает OverflowError.
- Вопрос автору: ограничивается ли вход числами, представимыми конечным float,
  или сверхбольшие int должны обрабатываться отдельно (нехватка дров / насыщение печи)?
- Статус: ожидает решения автора. Текущая реализация отклоняет непредставимое число
  с ValueError и текстом соответствующего параметра, сохраняя состояние.
  Авторских TC на такой случай нет. Это явно указанное ограничение текущей реализации.
