# Безумный транспорт: Ходячая избушка «Бабкин Экспресс»

Учебный проект по дисциплине «Сборка, тестирование и верификация программного продукта».

## Требования и запуск

Python 3.10 или новее. Внешних зависимостей нет; установка пакетов не требуется.
Команды выполняются из корня этого репозитория, где находятся SPEC.md и walking_hut/.

```bash
python -m unittest discover -v
```

На Linux/macOS команда интерпретатора может называться `python3`, на Windows — `py`.
Если `python` открывает Microsoft Store, установите Python и добавьте его в PATH
или укажите полный путь к интерпретатору.
Тесты выводят шаги и сохраняют логи в `tests/logs/` (каталог исключён из Git).

## Пример использования

```python
from walking_hut import HutOutOfFirewood, WalkingHut

hut = WalkingHut("Бабкин Экспресс", mass_kg=1000, leg_length_m=2)
print(hut.walk(100))       # 5.0 минут; осталось 98.0 дров
hut.turn_around()          # к путнику; осталось 97.5 дров
hut.step_over("fence")     # осталось 94.5 дров; позиция не меняется
hut.sit_down()
hut.add_firewood(20)       # запас ограничен 100.0
hut.stand_up()             # осталось 99.0 дров
print(hut.get_status())

try:
    hut.run(10000)
except HutOutOfFirewood as error:
    print(error)           # отказ сохраняет состояние
```

Избушка ходит, бегает, садится, встаёт, разворачивается, перешагивает препятствия
и пополняет печь сидя. Повреждение первой ноги вызывает хромоту, второй — посадку.
Ремонт вне контракта. Публичные атрибуты доступны только для чтения;
`get_status()` возвращает независимый словарь с шестью ключами.
`can_step_over()` проверяет позу, ноги и высоту, не учитывая запас дров.

## Проверка реализации 08.11.2026

До реализации: обнаружено 55 тестов, `FAILED (errors=80)` из-за NotImplementedError
в заглушках (число ошибок включает варианты subTest).
После реализации: `Ran 55 tests`, `OK`; авторские тесты и ТЗ не редактировались.
Дополнительно выполнены 50 проверок публичного интерфейса: защита от записи/удаления,
валидация, приоритеты, атомарность отказов, независимость снимков и большие значения.
Эти дополнительные проверки не меняют авторскую таблицу TC и не заменяют приёмку автора.

Сравнение достаточности дров сейчас точное по float; дробная математическая граница
может дать отказ из-за округления. Сверхбольшие int, не представимые конечным float,
отклоняются с ValueError. Оба вопроса и отсутствие даты заморозки описаны в BUGREPORT.md;
ответы автора ещё не получены.
